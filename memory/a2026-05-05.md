### 关键技术发现

1. **FileTable 偏移量指向原始 m2d 文件**：之前误以为偏移量指向解码/解压后的数据，但实际上每个文件是原始 m2d 中的独立 base64 块。偏移量直接对应原始文件的字节位置。

2. **每个文件独立加密**：`原始 m2d 块 → base64 分段解码 → AES-CTR 解密 → (可选 zlib 解压) → PNG/DDS`

3. **Base64 嵌入 `=` 分段**：m2d 内部使用非标准 base64，`=` 号是分段标记而非标准填充。需要按 `=` 分组逐段解码。

4. **所有文件使用 OS2F 密钥体系**：共 23 个密钥索引（0-125），每个 m2d 文件对应一个固定密钥索引。

- 当前提取的 XOR key 均为 2047 字节（缺 1 字节，regex 截断问题，需修正）

### 解密链（CryptoMan.cs）
1. M2H: base64 decode → AES-CTR(ECB) → zlib decompress → CSV/FileTable
2. M2D data: 由 buffer_flag 决定加密方式：
   - `0xEE00000X`: AES-CTR(base64 decoded) + optional zlib (X=压缩级别，0=无压缩)
   - `0xFF00000X`: XOR(2048-byte key) + optional zlib
3. .usm 文件使用 XOR buffer flag（0xFF000000，无压缩）
4. AES key 索引 = `compressed_size & 0x7F`
5. AES-CTR 实现：ECB 加密 counter（初始=IV），与数据 XOR，counter 小端递增

### Ghidra 输出分析
