
- Each blob is independently encrypted
- Large Image files contain ~14,355 encrypted blobs

- Image files use OS2F key table
- Key index = `compressed_size & 0x7F`
- Each m2d file may use different key index (no simple pattern)

**Now (CORRECT):**
- ✅ **FileTable V8 fully decrypted** (909,640 bytes = 22,741 entries × 40 bytes/entry)
- ✅ **Key selection formula: `key_index = file_size & 0x7F`** (NOT compressed_size!)
- ✅ **FileTable offset points to raw M2D file** (not decoded data)
- ✅ **Each file independently encrypted**, AES counter resets per file
- ✅ **Base64 block delimiter = V2 (block_size)** — not `==` separator

### FileTable Entry Structure (40 bytes)

```
struct FileEntryV8 {
    uint32_t v0;        // [0]  constant
    uint32_t index;     // [4]  file index (1-based)
    uint32_t v2;        // [8]  block_size (Base64 blob size)
    uint32_t v3;        // [12] 0
    uint32_t file_size; // [16] original file size → key_index = file_size & 0x7F
    uint32_t v5;        // [20] 0
    uint32_t v6;        // [24] file_size (duplicate)
    uint32_t v7;        // [28] 0
    uint32_t offset;    // [32] offset into raw M2D file
    uint32_t v9;        // [36] 0
};
```

### Per-File Decryption Flow

```
For each file (independent operation):
1. Read FileTable entry → (block_size, file_size, offset)
2. Read raw_m2d[offset : offset + block_size]
3. Base64 decode (remove trailing = padding, add proper pad)
4. AES-CTR decrypt: key_index = file_size & 0x7F, counter reset per file
5. If result[0] == 0x78 → zlib.decompress()
6. Validate magic: PNG (0x89504E47) / DDS (0x44445320) / BMP (0x424D)
7. Save to output path from Image.m2h.header
```

### Key Breakthrough: Exported.m2d is NOT AES Encrypted

**Critical finding from entropy analysis:**
- m2d base64 data entropy: 6.0 bits/byte (matches base64 of compressed data)
- Plaintext XML entropy: 5.22 bits/byte (text/XML)
- **If AES-CTR encrypted, entropy would be ~7.9 bits/byte**
- Conclusion: **Exported m2d data is ONLY base64 encoded, NOT AES encrypted**

### Confirmed Decryption Flow for Exported Files
```
raw_m2d_file → base64.b64decode() → zlib.decompress() → XML
              (NO AES encryption step)
```

### What This Means
- The `==` in base64 data are padding markers (not separators)
- Each blob in Exported.m2d decodes to compressed XML (zlib)
- FileTable entry contains: block_size, file_size, offset
