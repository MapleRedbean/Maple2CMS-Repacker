### Key Derivation Mismatch
- `compressed_header_size & 0x7F` does NOT produce the correct key index:
  - Image: 984866 & 0x7F = 34, but actual key = 80 ❌
  - Exported: 1039993 & 0x7F = 121, but actual key = 26 ❌
- The C# Encrypt code uses `uLenCompressed` (after zlib) for `GetKeyAndIV`, but the stored header field values don't match this derivation
- Hypothesis: the M2H files were created by Nexon's original tool (not Orion2 repacker), which may use a different key derivation

### FileTable (FT) Decryption — Still Blocked
- FT is a SEPARATE section in M2H, starting at offset `60 + encoded_header_size`
- Image.m2h: FT at offset 132620, 388,440 bytes; CSV zlib stream has 0 unconsumed tail
- Exported.m2h: FT at offset 96854, 175,152 bytes
- **Problem**: FT section contains 1 embedded `=` character that breaks base64 decoding
  - After removing `=`, length becomes 304,209 which is `1 mod 4` — invalid for base64
  - Need to handle by splitting at `=` or using segment-based decoding
- AES_ZLIB flag = 0x000000EE: bits[0]=0xEE (compress with zlib), bits[3]=0x00 (AES)
- XOR_ZLIB flag = 0xFF000000: bits[0]=0x00 (no compress), bits[3]=0xFF (XOR)

### M2H Header Field Values Discrepancy
- For Exported: compressed_header=1,039,993 > header_size=612,200 (compression should REDUCE size!)
- This is impossible for zlib compression → fields may have different meanings than assumed
- The `compressed_header_size` field might actually represent something else entirely
- Earlier finding that `encoded_header_size` = base64 text size appears correct for Exported (96,794 bytes)

### Key Findings
- Every game DLL has `.tvm0` section (PE section with TVM bytecode)
- All DLLs have AES references in combined native+TVM code
- FT decryption logic could be in ANY of these TVM sections
- All `.rdata`/`.data` sections searched: only standard AES S-Box/Rcon/CRC32 constants — NO additional key tables beyond Orion2's 128×4 keys
- TVM static RE requires first reverse-engineering the entire custom CPU ISA (~28.5 MB bytecode) → impractical without dedicated tooling
- Runtime hook approach requires running game client (loads all 6 DLLs)
